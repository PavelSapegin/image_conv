# Выводы по реализации и бенчмаркингу свёртки изображений

Для оценки эффективности собственного решения был проведен бенчмаркинг (с использованием `pytest-benchmark`) против популярных библиотек компьютерного зрения и обработки изображений - **OpenCV** и **Pillow**.

Основываясь на графике сравнения производительности (ось Y имеет **логарифмический масштаб**), можно сделать следующие выводы:

### 1. Абсолютное сравнение производительности (Рейтинг)
По скорости выполнения алгоритмы выстроились в следующем порядке:
1. **OpenCV** - во всех сценариях отрабатывает на 1-2 порядка быстрее остальных.
2. **Pillow** - показывает средний результат. Он медленнее OpenCV, но значительно обходит собственную реализацию.
3. **Custom (Собственная реализация)** - самый медленный подход. Разница в скорости с OpenCV доходит до 10-20 раз в зависимости от размера изображения.

### 2. Влияние размера изображения
Все три реализации демонстрируют ожидаемый рост времени выполнения при увеличении размера изображения (от $128\times128$ до $4096\times4096$). 
* Время растет пропорционально количеству пикселей.
* На графике это выглядит как линейный сдвиг вверх, однако из-за логарифмической шкалы реальное время выполнения растет квадратично относительно длины стороны (разрешение $4096\times4096$ обрабатывается примерно в 16 раз дольше, чем $1024\times1024$).

### 3. Влияние цветового режима (Color vs Gray)
Из сравнения левого (color) и правого (gray) столбцов графиков видно:
* Обработка изображений в оттенках серого (Gray, 1 канал) выполняется ожидаемо быстрее для всех реализаций, чем обработка полноцветных изображений (RGB, 3 канала). 
* При этом в собственной реализации нет медленных явных циклов по цветовым каналам. ### Архитектурное обоснование результатов (Почему Custom медленнее?)

То, что собственная реализация оказалась самой медленной - ожидаемый результат для Python. На это есть несколько причин:

1. **Python Overhead (Циклы `for`):** В собственной реализации  присутствует вложенный цикл по размеру ядра. Хотя внутри цикла используется векторизация NumPy (умножение срезов), сами итерации цикла происходят на уровне интерпретатора Python, что добавляет существенные издержки при каждом вызове.
2. **Отсутствие низкоуровневой оптимизации:** OpenCV написан на C++, оптимизирован и скомпилирован. Он не только избегает издержек Python, но и использует специфичные для процессора инструкции для параллельного умножения массивов чисел на аппаратном уровне.
3. **Многопоточность:** OpenCV "под капотом" умеет распараллеливать задачу на несколько ядер процессора, тогда как собственная реализация на Python выполняется строго в одном потоке. Pillow также использует оптимизированные C-расширения для своих фильтров.

### Итог
Проект демонстрирует суть операции свёртки изображений и работу с паддингами (valid, zero, edge, reflect). Написанный код подходит для учебных целей, понимания работы сверточных нейронных сетей (CNN) и цифровой обработки сигналов. Однако для продуктовых задач, требующих обработки изображений в реальном времени, необходимо использовать готовые высокооптимизированные инструменты на базе С или C++, такие как OpenCV.
